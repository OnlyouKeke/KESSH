# 第三方库编译说明（wolfSSL + libssh2）

本文档说明如何在 HarmonyOS 环境下使用 `scripts/build_third_party.sh` 一键编译
wolfSSL 与 libssh2，并给出常见问题排查提示。

## 1. 准备工作

1. 安装 HarmonyOS Native SDK，并将 `OHOS_NDK_HOME` 指向 SDK 根目录。
2. 准备基础构建工具：`cmake`、`curl`、`tar`，建议额外安装 `ninja` 以提升编译速度。
3. 确认网络环境可访问官方源码站点（`github.com/wolfSSL/wolfssl` 及 `libssh2.org`）。

```bash
# 示例：在 bash 中临时设置环境变量
export OHOS_NDK_HOME=/path/to/harmony/ndk
```

> **提示**：首次运行会下载源码包至 `third_party/downloads/`，后续执行会直接复用缓存。

## 2. 运行脚本

在仓库根目录执行：

```bash
./scripts/build_third_party.sh
```

脚本默认仅构建 `arm64-v8a`，产物输出目录为：

- `wolfssl-out/arm64-v8a`：包含头文件及静态库 `libwolfssl.a`；
- `libssh2-out/arm64-v8a`：包含头文件及静态库 `libssh2.a`（已链接 wolfSSL）。

### 可选参数

- `--abi <abi>`：指定目标 ABI（支持 `arm64-v8a`、`armeabi-v7a`、`x86_64`）；
- `--clean`：清理缓存的源码与构建目录后重新开始。

### 环境变量覆盖

- `WOLFSSL_VERSION`：默认 `5.7.0-stable`；
- `LIBSSH2_VERSION`：默认 `1.11.1`；
- `OHOS_API_LEVEL`：默认 `11`；
- `OUTPUT_ROOT`：覆盖输出根目录，默认为仓库根目录；
- `JOBS`：自定义并行编译任务数。

## 3. 在工程中的引用方式

在 `Application/entry/build-profile.json5` 的 `externalNativeOptions.arguments` 中，
为每个 ABI 填入类似的 CMake 变量即可：

```
"-DLIBSSH2_INCLUDE_DIR_ARM64=/absolute/path/libssh2-out/arm64-v8a/include"
"-DLIBSSH2_LIBRARY_ARM64=/absolute/path/libssh2-out/arm64-v8a/lib/libssh2.a;/absolute/path/wolfssl-out/arm64-v8a/lib/libwolfssl.a"
```

> **注意**：Windows 上建议使用正斜杠路径或在 `CMakeLists.txt` 中做路径规范化，
> 以避免转义字符导致解析失败。

## 4. 常见问题

- **报错找不到 sysroot**：确认 `OHOS_NDK_HOME/native/sysroot` 是否存在，若 SDK 目录结构不同，请调整脚本中的路径。
- **wolfSSL 编译失败**：检查是否具备所需的工具链；如网络受限，可提前手动将源码下载至 `third_party/downloads/`。
- **libssh2 找不到 wolfSSL**：确认 `wolfssl-out/<abi>` 目录完整，且在执行脚本前不要删除其中由 CMake 生成的文件。

## 5. 手工更新或增量编译

若只想重建某一个库，可删除对应的 `third_party/build/wolfssl-<abi>` 或
`third_party/build/libssh2-<abi>` 目录后重新运行脚本。脚本会跳过已安装的产物，直接覆盖安装结果。

---

如需将产物分发给其他项目，请将 `include/` 与 `lib/` 目录整体拷贝，并同步更新
`build-profile.json5` 中的参数，确保 NAPI 模块能够正确链接 wolfSSL 与 libssh2。
