# 第三方库编译说明（OpenSSL + libssh）

本文档说明如何在 HarmonyOS 环境下使用 `scripts/build_third_party.sh` 一键编译
OpenSSL 与 libssh，并给出常见问题排查提示。

## 1. 准备工作

1. 安装 HarmonyOS Native SDK，并将 `OHOS_NDK_HOME` 指向 SDK 根目录（脚本会依次
   查找 `build/cmake/ohos.toolchain.cmake` 与 `native/build/cmake/ohos.toolchain.cmake`
   以兼容不同版本的目录结构）。
2. 准备基础构建工具：`cmake`、`curl`、`perl`、`tar`，建议额外安装 `ninja` 加快编译速度。
3. 确认网络环境可访问官方源码站点（`openssl.org` 与 `libssh.org`）。

```bash
# 例：在 bash 中临时设置环境变量
export OHOS_NDK_HOME=/path/to/harmony/ndk
```

> **提示**：首次运行会下载源码包至 `third_party/downloads/`，后续执行会直接复用缓存。

## 2. 运行脚本

在仓库根目录执行：

```bash
./scripts/build_third_party.sh
```

脚本默认只构建 `arm64-v8a`，产物输出目录为：

- `openssl-out/arm64-v8a`：包含 `include/`、`lib/libcrypto.a`、`lib/libssl.a` 等文件。
- `libssh-out/arm64-v8a`：包含头文件与静态库 `libssh.a`。

### 可选参数

- `--abi <abi>`：指定目标 ABI（支持 `arm64-v8a`、`x86_64`）。
- `--clean`：清理缓存的源码与构建目录后再重新开始。

### 环境变量覆盖

- `OPENSSL_VERSION`：默认 `3.2.1`，可指定其他版本号。
- `LIBSSH_VERSION`：默认 `0.10.6`。
- `OHOS_API_LEVEL`：默认 `11`。
- `OUTPUT_ROOT`：覆盖输出根目录，默认为仓库根目录。
- `JOBS`：自定义并行编译任务数。

## 3. 在工程中的引用方式

在 `Application/entry/build-profile.json5` 的 `externalNativeOptions.arguments` 中，
对每个 ABI 填入如下 CMake 变量即可：

```json5
"-DLIBSSH_INCLUDE_DIR_ARM64=/absolute/path/libssh-out/arm64-v8a/include",
"-DLIBSSH_LIBRARY_ARM64=/absolute/path/libssh-out/arm64-v8a/lib/libssh.a",
"-DOPENSSL_INCLUDE_DIR_ARM64=/absolute/path/openssl-out/arm64-v8a/include",
"-DOPENSSL_LIBS_ARM64=/absolute/path/openssl-out/arm64-v8a/lib/libssl.a;/absolute/path/openssl-out/arm64-v8a/lib/libcrypto.a"
```

> **注意**：Windows 上建议使用正斜杠路径或在 `CMakeLists.txt` 中做路径规范化，
> 以避免转义字符造成解析失败。

## 4. 常见问题

- **报错找不到 sysroot**：确认 `OHOS_NDK_HOME/native/sysroot` 或
  `OHOS_NDK_HOME/sysroot` 是否存在，若 SDK 版本目录不同，请调整脚本中的路径。
- **OpenSSL 编译失败**：检查是否安装 `perl`；若网络受限，可提前手动下载源码包放入 `third_party/downloads/`。
- **libssh 找不到 OpenSSL**：确保 `openssl-out/<abi>` 目录完整，并在执行脚本前不要删除其中的 `cmake` 生成缓存。

## 5. 手工更新或增量编译

如果只想重建某一个库，可删除对应的 `third_party/build/openssl-<abi>` 或
`third_party/build/libssh-<abi>` 目录后重新运行脚本，脚本会跳过已安装的产物，直接覆盖安装结果。

---

如需将产物提交到其他项目中，请将 `include/` 与 `lib/` 目录整体拷贝，并同步更新
`build-profile.json5` 中的参数，确保 NAPI 模块能够正确链接 OpenSSL 与 libssh。
