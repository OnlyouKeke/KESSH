# 第三方库编译说明（wolfSSL + libssh2）

本文档说明如何在 HarmonyOS 环境下使用 `scripts/build_third_party.sh` 编译 wolfSSL 与 libssh2，并说明这些产物如何接入 `Application/entry` 的 C++ NAPI 模块。

## 1. 准备工作

1. 安装 HarmonyOS Native SDK，并将 `OHOS_NDK_HOME` 指向 SDK 根目录。
2. 准备基础构建工具：`cmake`、`curl`、`tar`，建议额外安装 `ninja` 以提升编译速度。
3. 确认网络环境可访问官方源码站点：`github.com/wolfSSL/wolfssl` 与 `libssh2.org`。

```bash
export OHOS_NDK_HOME=/path/to/harmony/ndk
```

首次运行脚本会下载源码包到 `third_party/downloads/`，解压源码到 `third_party/src/`，并将中间构建目录放在 `third_party/build/`。这些目录都是可再生材料，不应提交到版本库。

## 2. 编译 native 依赖

在仓库根目录执行：

```bash
./scripts/build_third_party.sh --abi arm64-v8a
./scripts/build_third_party.sh --abi x86_64
```

脚本会为指定 ABI 安装以下产物：

- `wolfssl-out/<abi>/include`
- `wolfssl-out/<abi>/lib/libwolfssl.a`
- `libssh2-out/<abi>/include`
- `libssh2-out/<abi>/lib/libssh2.a`

`Application/entry/build-profile.json5` 当前启用的 ABI 是 `arm64-v8a` 和 `x86_64`，因此这两个 ABI 的 wolfSSL 和 libssh2 产物都需要存在。

### 可选参数

- `--abi <abi>`：指定目标 ABI，支持 `arm64-v8a`、`armeabi-v7a`、`x86_64`。
- `--clean`：清理缓存源码与构建目录后重新开始。

### 环境变量覆盖

- `WOLFSSL_VERSION`：默认 `5.7.0-stable`。
- `LIBSSH2_VERSION`：默认 `1.11.1`。
- `OHOS_API_LEVEL`：默认 `11`。
- `OUTPUT_ROOT`：覆盖输出根目录，默认是仓库根目录。
- `JOBS`：自定义并行编译任务数。

## 3. 在工程中的引用方式

`Application/entry/src/main/cpp/CMakeLists.txt` 默认从仓库根目录读取：

- `wolfssl-out/${CMAKE_OHOS_ARCH_ABI}`
- `libssh2-out/${CMAKE_OHOS_ARCH_ABI}`

默认情况下不需要在 `Application/entry/build-profile.json5` 的 `externalNativeOptions.arguments` 中填写额外参数。当前工程不是通过旧的 `LIBSSH2_INCLUDE_DIR_ARM64` / `LIBSSH2_LIBRARY_ARM64` 参数接入第三方库。

如果运行脚本时设置了自定义 `OUTPUT_ROOT`，或者希望使用仓库外的预编译产物，可以通过 CMake 变量覆盖根路径：

```text
-DWOLFSSL_ROOT=/absolute/path/wolfssl-out/arm64-v8a -DLIBSSH2_ROOT=/absolute/path/libssh2-out/arm64-v8a
```

Windows 路径建议使用正斜杠，或确保反斜杠不会被 CMake/JSON 字符串转义。

## 4. 生成物治理

以下目录是可再生编译材料或本地输出，已经由仓库级 `.gitignore` 忽略：

- `third_party/downloads/`
- `third_party/src/`
- `third_party/build/`
- `wolfssl-out/`
- `libssh2-out/`
- `mbedtls-out/`

`mbedtls-out/` 是历史产物，当前 native SSH 构建链路使用 wolfSSL + libssh2，不再依赖 mbedTLS。第一轮工程化整理只停止跟踪这类历史输出，不要求物理删除本地目录。

## 5. 常见问题

- **报错找不到 sysroot**：确认 `OHOS_NDK_HOME/native/sysroot` 是否存在。若 SDK 目录结构不同，需要检查 HarmonyOS Native SDK 安装路径。
- **找不到 `libwolfssl.a` 或 `libssh2.a`**：确认已经为当前 ABI 运行 `scripts/build_third_party.sh --abi <abi>`，且 `Application/entry/build-profile.json5` 中的 ABI 与输出目录一致。
- **使用了自定义 `OUTPUT_ROOT` 后 CMake 找不到库**：在 `externalNativeOptions.arguments` 中传入 `-DWOLFSSL_ROOT=...` 和 `-DLIBSSH2_ROOT=...`，指向对应 ABI 的安装目录。
- **网络受限导致下载失败**：可以提前手动下载源码包到 `third_party/downloads/`，文件名需与脚本期望一致。

## 6. 增量或重新编译

若只想重建某个 ABI，可删除对应中间目录后重新运行脚本：

- `third_party/build/wolfssl-<abi>`
- `third_party/build/libssh2-<abi>`

如果希望同时清理缓存源码和构建目录，使用：

```bash
./scripts/build_third_party.sh --abi arm64-v8a --clean
```

脚本会重新生成并覆盖安装到 `wolfssl-out/<abi>` 和 `libssh2-out/<abi>`。
